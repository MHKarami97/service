# مدیریت سرویس (service.mhkarami97.ir)

اپلیکیشن مدیریت تاریخچه و یادآوری سرویس‌های دوره‌ای وسایل خانه (یخچال، کولر،
لباسشویی، ظرفشویی، پکیج، آبگرمکن و ...) و وسایل نقلیه (خودرو).
ساختار و الگوهای این پروژه از روی پروژه «خرید هوشمند» (Shopping Checklist)
همان خانواده معماری کپی و برای این دامنه بازطراحی شده است.

## پشته فنی
Vue 3 (Composition API, `<script setup>`) + Pinia + Vue Router + Vite +
Tailwind CSS + vite-plugin-pwa، فونت Vazirmatn، RTL کامل، Mobile-first.

## معماری و الگوهای طراحی (Design Patterns)

| الگو | محل استفاده | دلیل |
|---|---|---|
| Aggregate Root (DDD) | `ServiceableItem` | تمام تغییرات تاریخچه سرویس فقط از طریق این کلاس مجازند تا فیلدهای مشتق‌شده (lastRecord، nextServiceDate، totalSpent) هرگز ناسازگار نشوند. |
| Template Method | `ServiceableItem.getDueStatus()` | منطق مقایسه تاریخ در کلاس پایه است؛ `Vehicle` فقط سیگنال کیلومتر را با override کردن `extraDueSignal()` اضافه می‌کند، بدون تکرار کد. |
| Factory | `ServiceableItemFactory` | تنها نقطه ساخت نمونه‌های `Vehicle`/`Appliance` از روی کاتالوگ، ورودی سفارشی یا JSON بازیابی‌شده. |
| Repository | `ServiceRepository` / `StorageService` | UI هیچ‌گاه مستقیم با localStorage کار نمی‌کند؛ جایگزینی با IndexedDB بدون تغییر مصرف‌کننده‌ها ممکن است. |
| Observer | Pinia store (`serviceStore`) | هر تغییر state به همه کامپوننت‌های مصرف‌کننده منتشر می‌شود. |
| Value Object | `defaultServiceCatalog.js` | داده‌ی مرجع فقط‌خواندنی که هرگز per-user ذخیره نمی‌شود؛ فقط پیشنهاد نوع سرویس را تغذیه می‌کند. |

## مدل دامنه

```
ServiceableItem (abstract, Aggregate Root)
 ├─ Vehicle   → currentOdometer, nextServiceOdometer, extraDueSignal() بر اساس کیلومتر
 └─ Appliance → location

ServiceRecord (Entity در دل Aggregate)
 - performedAt, cost, partsUsed[], serviceType, location
 - nextServiceDate
 - serviceOdometer / nextServiceOdometer (فقط برای Vehicle نمایش داده می‌شود)
 - description
```

هر `ServiceableItem` می‌تواند چند `ServiceRecord` داشته باشد. `lastRecord`
(جدیدترین بر اساس `performedAt`) منبع «تاریخ سرویس بعدی» و «کیلومتر سرویس
بعدی» است که در کارت هر وسیله و صفحه جزئیات آن نمایش داده می‌شود.

## کاتالوگ پیش‌فرض
`src/data/defaultServiceCatalog.js` شامل سمند سورن (با همان لیست سرویس‌هایی
که خودتان مشخص کردید: تعویض روغن، لنت ترمز، روغن هیدرولیک، روغن ترمز، چرخ،
تسمه تایم، شمع، فیلتر سوخت، آپدیت ECU، سرویس انژکتور، ترمز عقب، ضدیخ،
کمک‌فنر و جلوبندی، دیسک و صفحه کلاچ، سرویس کامل موتور، بیمه شخص ثالث و بدنه،
معاینه فنی) به‌همراه چند مورد اضافه‌ی کاربردی (فیلتر هوا، فیلتر کابین، باتری،
آلاینمنت، روغن گیربکس) و کولر، لباسشویی، ظرفشویی، یخچال + چند دستگاه خانگی
دیگر (آبگرمکن، پکیج، تصفیه آب، موتور درب پارکینگ) که خودم به‌عنوان موارد
کاربردی اضافه کردم؛ در صورت نیاز آزادانه ویرایش کنید.

در اولین اجرا (وقتی هنوز چیزی در localStorage ذخیره نشده) پنج مورد
(سمند سورن، کولر، لباسشویی، ظرفشویی، یخچال) به‌صورت خودکار به «وسایل من»
اضافه می‌شوند (`seedItemIds`). موارد دیگر کاتالوگ از دکمه «+ افزودن وسیله»
در دسترس‌اند.

## ویژگی‌ها
- ثبت/ویرایش/حذف هر رکورد تاریخچه سرویس با فیلدهای: تاریخ انجام، هزینه،
  وسایل/قطعات استفاده‌شده (چیپ‌های قابل افزودن با Enter یا دکمه)، نوع سرویس
  (با پیشنهاد سریع از کاتالوگ)، محل انجام، توضیحات، تاریخ سرویس بعدی، و برای
  خودرو: کیلومتر سرویس و کیلومتر سرویس بعدی.
- صفحه هر وسیله همیشه «تاریخ سرویس بعدی» و «کیلومتر سرویس بعدی» (برای
  خودرو) را از آخرین تاریخچه به‌صورت برجسته نمایش می‌دهد.
- وضعیت رنگی (به‌موقع / رو به اتمام / گذشته از موعد) بر اساس تاریخ و — برای
  خودرو — فاصله کیلومتر فعلی تا کیلومتر سرویس بعدی.
- صفحه «سرویس‌های پیش رو» همه وسایل را بر اساس فوریت مرتب می‌کند.
- خروجی/ورودی JSON کامل برای پشتیبان‌گیری.

## راه‌اندازی
```bash
npm install
npm run dev      # توسعه
npm run build    # خروجی نهایی در dist/
```

## استقرار روی service.mhkarami97.ir
1. فایل `CNAME` از قبل روی `service.mhkarami97.ir` تنظیم شده است.
2. پوشه‌های `public/fonts` و `public/icons` و `public/.well-known` را از
   پروژه اصلی («خرید هوشمند») کپی کنید — چون فایل‌های باینری (فونت woff2،
   آیکون PNG) در این خروجی قرار نگرفته‌اند.
3. با گیت‌هاب اکشن موجود (`.github/workflows/deploy.yml`) روی GitHub Pages
   دیپلوی کنید و در تنظیمات دامنه سفارشی مقدار `service.mhkarami97.ir` را
   ثبت کنید.

## نکات باز برای توسعه بعدی
- افزودن نمودار هزینه سرویس در طول زمان (Chart.js) بر اساس `item.history`.
- افزودن پیوست فاکتور/تصویر با IndexedDB (چون localStorage برای Blob مناسب
  نیست) — در همین معماری فقط باید یک `AttachmentRepository` جدید کنار
  `ServiceRepository` اضافه شود؛ به مدل موجود آسیبی نمی‌زند.
- Web Push یا Local Notification برای یادآوری سرویس‌های نزدیک (`soon`).
